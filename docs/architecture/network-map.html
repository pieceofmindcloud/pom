POM Network Map

A visual explanation of the POM network: one machine, one cluster, many clusters, and the roles that keep the network safe as it grows. The diagrams use generic machine names only.

Cluster = one POM network with one trust chain Node = one machine running one POM binary Pipeline = model layers split across nodes Gateway = the node that receives a client request

1. The unit: every node is a full POM machine

Key idea. A node is not an IP address. Its identity is a long-lived Ed25519 key. The node id, iroh endpoint id, pkarr key, TLS certificate, and authority key all derive from that key.

Ports. The defaults are UDP P2P 42777, inference QUIC 43777, gateway QUIC 44777, iroh endpoint and relay 52777, HTTP gateway 8080, and inference HTTP 8181. Different machines may use the same numbers.

Model source. The model is not passed on the command line. It is deployed through the UI, and each serving node loads its assigned layer range locally.

2. One cluster: a model pipeline across machines

Pipeline order is layer order. Whoever holds layer 0 receives the whole prompt. Each next node receives hidden state, runs its own layers, and passes the state onward.

Any node can be the gateway. The client request enters through one node's gateway port, but the inference runs across the planned pipeline. There is no local fallback when the pipeline does not cover all layers.

No weights travel because of slicing. Each peer extracts its own range from its own copy. File transfer is a separate operator action.

Idle is active. A peer can unload when idle, keep announcing its range, and be woken by the first request.

3. Roles: who may do what

Principal. The network's root authority. It can change settings, mint or rotate the connection key, grant or demote admins, approve admissions, remove members, and deploy models.

Secondary admin. A practical operator role. It can deploy models, approve admissions, view logs, and remove workers or visitors. It cannot change the network's core settings, keys, admins, or trust chain.

Worker. Hardware that serves model layers. It can participate in serving routes, but it has no administrative authority.

Visitor. A proxy node. It can run inference through the cluster, but it refuses to hold or serve a model, even if an admin asks.

Connection key. Every member holds it, including visitors. It authenticates transport and node-to-node calls, but by itself it opens no administrative route.

4. How nodes find each other and prove membership

Discovery is not membership. A node may learn an address from UDP, mDNS, pkarr, or gossip, but it only becomes a peer after local admission proof.

Private networks. Admission uses the connection key through a challenge handshake. The key never travels; the peer proves it knows the key and signs with its node key.

Public networks. Admission checks the announced key against the local trust chain, or, in the older open mode, checks that the node holds the matching anchor.

Transport. Node-to-node HTTP is mutual TLS with certificates pinned to node ids. The iroh path uses QUIC under the node key, relays, and hole punching.

pkarr. A public key-to-address resolver. It publishes only public addresses and relay hints, never private LAN addresses.

5. How a new machine joins a cluster

Own network is never dropped. The network a node created at first launch is inherent to it. Joining another network puts the own network into standby. Leaving restores it.

Leaving costs the key. A member tells the principal before going silent. The principal forgets the admission and rotates the connection key, unless the network is in the open mode.

Key rotation does not cut inference. The new key has a transition window. Nodes keep sending the old key briefly and accept both keys briefly, so in-flight work survives.

Offline member. A member that missed a rotation can claim the new key through the lobby, if it is still on the principal's member list.

6. Multiple clusters: how the network looks when it grows

One active network per process. The current runtime keeps a single P2P network per node process. A node can move between networks, but it does not serve two clusters at the same time.

Clusters do not merge. Each cluster has its own principal, trust chain, cluster id, connection key, policies, and deployment history.

Shared relays are not shared membership. All clusters share the announce topic, and relays can meet traffic from different networks. A peer announcing another cluster id is refused outright.

Public directory. Public networks can publish signed descriptions. A relay can gather or receive them. A candidate can read the directory and ask to join, but listing is not membership.

Growth pattern. A large deployment becomes many clusters: a lab cluster, a datacenter cluster, a public community cluster, and a private cluster. Machines move between them by leaving one and joining another.

7. A grown network: typical shapes

Principal control cluster

A small cluster of admin machines. The principal holds settings and keys. Secondary admins run deployments and admissions.

Worker serving pool

GPU and RAM machines serve layer ranges. Some machines hold whole models, some hold slices, some hold several non-adjacent ranges.

Visitor edge nodes

Laptops, branch offices, or public entry points route inference into the cluster without holding model weights.

Relay shared meeting point

A reachable node or dedicated relay helps NATed nodes meet. It is transport infrastructure, not a member of every cluster.

Secondary admin operations

Day-to-day operators deploy models, approve machines, inspect telemetry, and remove bad members without touching core keys.

Idle capacity

Idle workers keep their announced ranges but unload the model. The first request wakes them in parallel before planning continues.

8. Request path through a grown cluster

Gateway is not a special machine. Any node can receive the client request. The difference is that the gateway runs the planning and admission for that request.

Head is special. The node holding layer 0 receives the whole prompt. The tail performs sampling and produces the answer.

Parallel routes. Exact replicas of the same range are valid. The router can choose the copy with better measured latency and load.

Tensor parallel. A group of ranks runs one collective stage. The gateway talks to rank 0, and rank 0 keeps the ranks in lockstep.

9. What to say to new people

Start with identity

Every machine has a key. The network trusts keys, not IPs. That is why a laptop can move networks and keep its identity.

Then explain roles

Principal owns the network. Secondary admin operates deployments. Workers serve layers. Visitors route requests.

Then show the pipeline

A model is split by layers. The pipeline order is the layer order. The whole prompt enters at layer 0.

Then show growth

Large systems become many clusters. They may share relays and public listings, but each cluster keeps its own trust and keys.
