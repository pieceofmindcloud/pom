# Goal FreeToken e caminho MoE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adicionar políticas de memória e cancelamento, bifurcar MoE de forma segura e entregar um executor MoE próprio com cache LRU e co-execução medida, sem alterar o caminho denso.

**Architecture:** O GGUF classifica o modelo. Denso continua no `LlmEngine`; MoE usa módulos próprios depois da Fase 3. Políticas puras ficam fora do FFI e o runtime mantém pesos separados de contextos para permitir rebuild sem reler o arquivo.

**Tech Stack:** Rust 2021, Tokio, Axum, serde, GGUF, `llama-cpp-sys-2`, testes unitários e labs de inferência existentes.

**Spec:** `docs/superpowers/specs/2026-08-24-ftk-moe-design.md`

## Global Constraints

- O caminho denso continua usando `llama.cpp` e não pode cair no executor MoE.
- Nenhum peso trafega na rede por causa do fatiamento.
- Não copiar código do FreeToken; reimplementar a partir do entendimento.
- Não manter fallback de protocolo antigo nem alterar contrato de fio sem decisão.
- Não afirmar desempenho sem medição local reproduzível.
- Cada fase termina com documentação atualizada, teste e commit em `feat/ftk`.
